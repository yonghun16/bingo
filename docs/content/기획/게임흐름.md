웹 기반 멀티플레이어 빙고 게임 프로토타입을 만들어줘. 아래 스펙대로 구현해줘.

## 기술 스택
- 프론트엔드: React (Vite)
- 백엔드: Node.js + Express + Socket.io (실시간 통신)
- 데이터 저장: 인메모리(서버 재시작 시 초기화, DB 없이 진행)
- 프로토타입이므로 로그인/인증 없이 닉네임 기반으로만 진행

## 전체 흐름

1. **방 만들기**
   - 첫 유저(방장)가 "방 만들기" 버튼을 누르면 고유한 room ID가 생성되고 방장은 닉네임을 입력한 뒤 방에 입장한다.
   - 방장에게 공유 가능한 초대 링크(예: https://.../room/{roomId})가 표시된다.

2. **입장**
   - 다른 유저는 링크로 접속하면 닉네임 입력 화면이 뜨고, 입력 후 방에 입장한다.
   - 방 정원은 최대 5명. 5명이 이미 있으면 "방이 가득 찼습니다" 안내와 함께 입장이 거부된다.
   - 이미 게임이 시작된 방에는 입장할 수 없다(관전 기능은 프로토타입에서 제외).

3. **대기실 / 빙고판 세팅 화면**
   - 화면은 좌우 2분할: 왼쪽 = 본인 빙고판(5x5), 오른쪽 = 실시간 채팅창.
   - 유저는 1~25 숫자를 자신이 원하는 칸에 자유롭게 배치한다(숫자를 클릭 → 원하는 빈 칸 클릭 방식, 또는 드래그앤드롭).
   - 1~25 숫자를 전부, 중복 없이 25칸에 채워야 "준비 완료" 처리된다.
   - 참가자 목록에 각 유저의 준비 상태(대기중/완료)를 표시한다.
   - 방에 있는 모든 인원(최소 2명 이상)이 빙고판을 완성하면 자동으로 게임이 시작된다.

4. **게임 진행 (턴제)**
   - 참가자들은 입장 순서대로 턴을 갖는다.
   - 현재 턴인 유저는 10초 안에 아직 불리지 않은 숫자(1~25) 중 하나를 선택해서 호출해야 한다.
   - 10초 안에 선택하지 않으면 서버가 남은 숫자 중 하나를 랜덤으로 자동 호출하고 다음 턴으로 넘어간다.
   - 숫자가 호출되면 모든 참가자의 빙고판에서 해당 숫자가 있으면 자동으로 마킹된다(본인 것뿐 아니라 전원의 보드에 동일하게 적용).
   - 이미 호출된 숫자는 다시 호출할 수 없다(선택 불가 처리).
   - 가로 5줄, 세로 5줄, 대각선 2줄 = 총 12개 라인 중 3줄을 완성하면 그 유저가 우승자가 된다.
   - 화면에는 항상 다음 정보를 표시: 현재 턴 유저, 남은 시간(10초 카운트다운), 지금까지 호출된 숫자 목록, 각 유저의 완성 라인 수.

5. **게임 종료**
   - 누군가 3줄을 완성하는 순간 게임이 즉시 종료된다.
   - 모든 참가자의 빙고판이 전원에게 공개된다(마스킹 해제).
   - "🎉 {닉네임}님이 우승했습니다!" 형태의 종료 메시지를 모달 또는 배너로 표시한다.
   - 동시에 여러 명이 같은 호출로 3줄을 달성하면 공동 우승으로 처리한다.
   - 게임 종료 후에는 "다시 하기" 버튼으로 같은 방에서 새 게임을 시작할 수 있게 한다(빙고판 초기화 → 다시 세팅 단계로).

6. **채팅**
   - 화면 오른쪽에는 게임 시작 전/후 내내 사용 가능한 실시간 채팅창이 있다.
   - 닉네임 + 메시지 + 타임스탬프 형식으로 표시.

## 데이터 모델 (참고용)

Room {
  roomId: string
  players: Player[]  // 최대 5명
  status: 'waiting' | 'playing' | 'ended'
  currentTurnIndex: number
  calledNumbers: number[]
  winner: Player | Player[] | null
  chatMessages: ChatMessage[]
}

Player {
  id: string (socket id)
  nickname: string
  board: number[][] | null   // 5x5, null이면 아직 세팅 중
  markedNumbers: number[]
  isReady: boolean
  completedLines: number
  joinOrder: number
}

## 소켓 이벤트 (참고용, 필요시 이름 조정 가능)
- create_room / join_room / room_full / room_not_found
- set_board (본인 보드 제출)
- player_ready_update (준비 상태 브로드캐스트)
- game_start
- your_turn / turn_timeout
- call_number (클라이언트 → 서버)
- number_called (서버 → 전체, 마킹 정보 포함)
- game_over (우승자, 전체 보드 공개 데이터 포함)
- send_chat / chat_message
- restart_game

## UI 요구사항
- 반응형까지는 필요 없고 데스크톱 기준 레이아웃으로 충분.
- 좌: 빙고판(세팅 단계엔 숫자 배치용, 게임 단계엔 마킹 표시), 우: 채팅 + 참가자 목록/턴 정보.
- 턴 타이머는 시각적으로 눈에 띄게(카운트다운 숫자 또는 프로그레스 바).
- 최소한의 스타일링은 하되 화려한 디자인은 프로토타입 단계에서 생략 가능.

## 예외 처리
- 게임 중 유저 접속 종료(disconnect) 시: 해당 유저는 자동 기권 처리하고 나머지 인원으로 게임 계속 진행. 세팅 단계에서 나가면 그냥 인원에서 제외.
- 방장이 나가도 방은 유지(별도의 "방장 위임" 로직은 프로토타입에서 생략 가능).
- 숫자를 중복 배치하거나 25칸을 다 못 채운 상태로 준비 완료를 누르면 에러 메시지 표시.

먼저 서버(Express + Socket.io)의 방/게임 상태 관리 로직부터 만들고, 그 다음 프론트엔드 화면(방 만들기 → 대기실/보드 세팅 → 게임 진행 → 종료)을 순서대로 구현해줘. 구현 중간중간 진행 상황을 알려줘.
